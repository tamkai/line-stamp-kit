# stamp-plan — スタンプの計画をつくる（第1段階）

**ユーザーとのやり取りは必ず日本語で行う。**

参照画像（自分の写真・手描きキャラなど）と「何に使うか」から、**計画JSON（`stamp_plan.json`）** を作る。
**このスキルは画像を作らない。** 作るのは計画だけ。

## なぜ二段階なのか（利用者に必ず伝えること）

「スタンプ作って」と一息で頼むと、AI は表情の中身と絵柄を同時に決めて、いきなり画像を作り始める。
画像 1 枚に 1.5〜5 分かかるので、「この文字じゃなかった」「この表情いらない」が後から出ると
時間も Codex の使用量も無駄になる。

**表情と文字の一覧を、人が読めるファイルとして一度止める**と、そこを直すだけで済む。

計画JSONができた時点で必ずこう伝える:

> ここで一度止まります。表情・ひとこと・個数・絵柄を見て、直すところがあれば言ってください。
> ここで直す方が、画像になってから直すよりずっと速いです。

## Step 0: 環境チェック（初回のみ・自動）

`~/.line-stamp-kit-ready` が存在しなければ、stamp-setup の手順を実行してから続行する。
存在して `stamp_make: available` なら黙って次へ進む。`unavailable` なら、計画を作る前に
「このパソコンでは画像生成が確認できていない」と伝え、stamp-setup で直すか相談する。
**利用者に環境の話をさせない。**

## Step 1: 参照画像と権利の確認

聞くことは最大 2 つ。**1 問ずつ**聞く。

1. **元にする画像はあるか**
   - 自分の写真・自作キャラの絵 → その画像を作業フォルダに `reference.png`（jpg 可）として置いてもらう。**正面と横顔の 2 枚**があると髪型・ひげの再現が上がる（`reference` を配列にする）。スマホ写真は 3000px 級で重いので、顔と上半身に切り出して 1024px 程度に縮小する。机・PC・壁が写っていれば `character_note` に「背景は無視」と書く
   - 無い → 文章でキャラを決める（Step 5 の `character_note` を厚めに書く）
2. **権利**（参照画像が「人」のとき）
   - 本人か、本人の許可があるか。**他人・有名人・版権キャラは申請できない**（`references/line-guideline.md`）
   - 許可がないなら止める。代案として「似せない架空キャラ」を提案する

## Step 2: 用途を聞く

> どんな場面で使うスタンプですか？（例: 仕事の連絡 / 家族と / 友だちと / 推し活 / 自分の宣伝）

これで表情セットの方向と口調（丁寧 / フランク）が決まる。1 問だけ。深掘りしない。

## Step 3: 個数を決める

> 何個にしますか？ 8 / 16 / 24 / 32 / 40 から選べます。**初めてなら 8 個**がおすすめです。

伝えること:
- **申請後は個数を変えられない**（`references/line-guideline.md`）
- 個数 × 2〜5 分の生成時間がかかる。作り直しも含めると 8 個で 40〜60 分が目安
- **Codex の使用量: 画像 1 枚 ≒ Plus の 5 時間枠の約 2%**（実測）。8 個セットは試し打ち・作り直し込みで約 25%、16 個で約 45%。**24 個以上は 1 つの 5 時間枠に収まらない**ので、枠のリセットをまたいで分けるか Pro プランで。始める前に ChatGPT の「プランの利用上限」で残量を見てもらう

## Step 4: 表情とひとことを決める

**先に案を出す。** `references/expression-catalog.md` から用途に合うものを選び、
個数ぶんの一覧（番号・表情/ポーズ・文字）を **表で** 見せる。利用者は「3 番を変えて」「もっとゆるく」と直すだけ。

守ること:
- 文字は **2〜8 字**。長いとトーク画面で読めない
- 表情・ポーズは **体の動きと小道具で**書く（「嬉しい」より「両手を上げてジャンプ」）
- **文字なし**を 1〜2 個入れると使い道が広がる
- 同じ意味の言い換え（了解 / OK / わかった）を並べすぎない
- 表情の書き方のコツはカタログ末尾を参照

**利用者が OK と言うまで、この表を直す。** ここが計画の心臓部。

## Step 5: 絵柄とキャラの固定特徴を決める

絵柄は **同梱のギャラリーを見て選んでもらう**。名前と説明だけでは選べない（実物を見ると印象が変わる）。

```
<plugin>/skills/stamp-plan/styles/gallery.html     ← ブラウザで開いてもらう（サーバー不要）
```

同じマスコット・同じ表情・同じ文字を絵柄だけ変えて並べたページ。利用者は気に入ったものをクリックして名前をコピーするだけ。
Claude Code なら `open` / `start` で開いてよい。開けない環境なら `styles/gallery/<style>.png` を順に見せる。

| 名前 | 見た目 | 向く用途 |
|---|---|---|
| `bold-outline` | 極太の均一な黒線・フラットなくすみ色・影なし・ゆるカワ | 文具ブランド風。いちばん「スタンプらしい」 |
| `atsunuri` | 厚塗り・光沢・彩度高め・太い白フチ | 本人・知人を元にした「映える」もの |
| `flat-vector` | 線なし・図形で構成・大胆な限定色 | モダン・デザイン寄り。仕事の連絡にも |
| `line-watercolor` | インクの線×水彩のにじみ・やさしい色 | 家族・季節・やわらかい雰囲気 |
| `yuru-tegaki` | ゆるい手描きマーカー・色少なめ・脱力系 | 日常会話・ネタ |
| `clay` | マットなクレイ風 3D・やわらかい陰影 | マスコット・キャラもの。似顔絵の再現度が高い |

**ここで 1 つに決めてよい。** 迷って 2 つ残るなら両方を計画に書いておく（`style` に本命、`style_alt` に対抗）。
stamp-make の最初の工程で、本人の参照画像を使って **選んだ絵柄だけ試す**か **全絵柄で自分を描いてみる**かを選べる（後者は 6 枚並列・5〜8 分）。
ギャラリーで決めきれない人には「stamp-make で全部の絵柄で自分を描いて見比べられます」と伝えて、ここでは仮決めで進む。

続けて **`character_note`（毎回同じにする特徴）** を 1〜2 文で決める。
参照画像を見て「黒髪短髪・丸メガネ・紺のジャケット」のように**見た目の要素を列挙**する。
参照画像がない場合はここが唯一のキャラ定義になるので、髪・目・服・小物・雰囲気まで書く。

**メイン画像**（ストアや一覧に出る 1 枚）はどの番号にするかも決める。
そのキャラらしさが一番出る笑顔・決めポーズ。既定は 1 番。

## Step 6: 計画JSONを書いて止まる

作業フォルダ `<作業プロジェクト>/<スタンプ名>/` を作り、そこに `stamp_plan.json` を書く。
**プラグイン配下や `~/.claude/` には書かない**（後段で Codex がそこに書けず詰まる）。

```
<作業プロジェクト>/<スタンプ名>/
├── stamp_plan.json     ← このスキルの出力
└── reference.png       ← 利用者が置く（任意）
```

スキーマ（実例は `assets/stamp_plan.example.json`）:

| フィールド | 用途 |
|---|---|
| `title` | セット名（申請時のタイトル案にもなる） |
| `count` | 8 / 16 / 24 / 32 / 40 |
| `main` | メイン画像にする番号 |
| `style` | `styles/` のファイル名（拡張子なし）。ギャラリーで選んだもの |
| `style_alt` | （任意）対抗の絵柄。stamp-make の試し打ちで並べて比較する |
| `reference` | 参照画像のファイル名（作業フォルダからの相対）。**配列で複数可**（正面＋横顔など。同一人物の別アングルとして総合される）。無ければ省略 |
| `character_note` | 毎回同じにするキャラの見た目（1〜2 文） |
| `text_style` | （任意）文字の書体の指示。既定「手描きの太いマーカー風の日本語文字」 |
| `usage` | （任意）用途メモ。生成には使わないが、後で見返すときの文脈 |
| `stamps[]` | `no`（1 から連番）、`expression`（表情・ポーズ）、`text`（文字。なしは `""`） |

書いたら **一覧表をもう一度見せて**、冒頭の「ここで一度止まります」を伝える。
そのまま続ける流れなら:

> このまま作るなら「これをスタンプにして」と言ってください（stamp-make に進みます）。

## やってはいけないこと

- 計画の段階で画像を生成しない（1 枚の試作も stamp-make の仕事）
- 用途・個数・表情・絵柄を **一度にまとめて聞かない**。1 問ずつ
- 表情の案を出さずに「どんな表情にしますか？」と丸投げしない
- 提供元・イベント名・受講形態など、このキットの外の文脈を勝手に書かない。汎用の道具として振る舞う
