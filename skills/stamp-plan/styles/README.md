# styles/ — 差し替え可能な絵柄の定義

各 `*.txt` が1つの絵柄（画風）を定義する。stamp-make はこの全文を各スタンプの生成プロンプトに
差し込み、全スタンプの画風を揃える。**スタイルを足せば、同じ計画JSONから別の絵柄のスタンプが作れる。**

## 同梱スタイル

**まず `gallery.html` をブラウザで開く。** 同じマスコット・同じ表情・同じ文字で全絵柄を並べた見本（`gallery/<style>.png`）。
利用者はこれを見て選ぶ。名前と説明だけでは選べない（実物を見ると印象が変わる）。

| 名前 | 見た目（設計の文法が違う） | 向く用途 |
|---|---|---|
| `bold-outline` | **極太で均一な黒線**・フラットなくすみ色・影なし・単純な顔 | 文具ブランド風。いちばん「スタンプらしい」 |
| `atsunuri` | **厚塗り・光沢**・彩度高め・太い白フチ | 本人・知人を元にした「映える」もの |
| `flat-vector` | **線なし・図形で構成**・大胆な限定色（髪が紺でもよい） | モダン・デザイン寄り |
| `line-watercolor` | **インクの線×水彩のにじみ**・やさしい色 | 家族・季節・やわらかい雰囲気 |
| `yuru-tegaki` | **よれた手描きマーカー**・色少なめ・脱力系 | 日常会話・ネタ |
| `clay` | **マットなクレイ風 3D**・やわらかい陰影 | マスコット・キャラもの。似顔絵の再現度が高い |

**絵柄は「仕上げの質感」ではなく「設計の文法」で分ける。** 線の有無と太さ、塗り（フラット / 陰影 / 立体）、頭身、顔の記号化の度合い、
文字の書体、配色の写実度。同じ参照写真・同じポーズ・同じ文字で描くと、質感だけの違いは埋もれて「バリエーション違い」に見えてしまう（2026-09-04 実測）。

## 背景はクロマキー

全スタイルの冒頭で「背景はキャンバス全面フラットな単色（既定 #00ff00）」を要求する。Codex 組み込みの画像生成は参照画像を付けると
透過 PNG を返さないため、生成後に同梱ヘルパーで色を抜く（詳細は stamp-make の「透過の仕組み」）。
新しいスタイルを書くときもこの冒頭 2 行は残す。

## ギャラリーの更新（保守用）

絵柄を足したり直したりしたら、ギャラリーも作り直す:

```bash
# 1) 参照画像なしのマスコット計画で全絵柄を試し打ち（_dev/gallery/ を参照）
python3 ../../stamp-make/scripts/build_prompts.py --plan <gallery作業フォルダ> --sample-style <style> --no-reference
python3 ../../stamp-make/scripts/run_codex.py     --plan <gallery作業フォルダ> --sample-style <style>
# 2) 縮小して styles/gallery/ に配置し gallery.html を組む
python3 ../scripts/build_gallery.py --samples <gallery作業フォルダ>/output/samples
```

## 使い方

- 計画JSON（`stamp_plan.json`）の `"style": "atsunuri"` のように名前で指定する
- **作業フォルダに `style.txt` を置くと、そちらが優先される**。同梱スタイルをコピーして
  好みに書き換えるときはこの方法を使う（このプラグイン配下は書き換えない）

## 新しいスタイルの作り方

`atsunuri.txt` を雛形にコピーして書き換える。守ること:

1. **冒頭の 2 行**（正方形・1 枚だけ・フラットな単色背景）は残す
2. **Visual Style**: 既存の 6 種と**文法が違う**ことを確認してから書く。線の有無と太さ・塗り・頭身・顔の記号化・文字の書体・配色の写実度
3. **Sticker outline**: 白フチを付けるか、太さはどうか
4. **Cross-stamp consistency**: 全スタンプで同じ質感・線幅・彩度・頭身を保つ、と明記する
5. **TEXT RULE**: 日本語文字の扱い。「指定された文字だけを、一字一句その通りに」を必ず書く
6. 末尾は `## This stamp (spec follows):` で終える。その後に各スタンプの内容が連結される
